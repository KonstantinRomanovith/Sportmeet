# Учётные записи в основной базе

В комплектной `instance/sportmeet.sqlite3` уже есть **30 пользователей** для проверки всех пяти зарегистрированных ролей. Для входа на `http://127.0.0.1:5000/login` используйте общий начальный пароль **`SportRyadom26!`**.

| Роль | Логин |
|---|---|
| Участник | `participant@sportmeet.local` |
| Организатор | `organizer@sportmeet.local` |
| Администратор площадок | `venue-admin@sportmeet.local` |
| Администратор мероприятий | `event-admin@sportmeet.local` |
| Глобальный администратор | `global-admin@sportmeet.local` |

Дополнительные логины: участники `participant02@sportmeet.local` … `participant20@sportmeet.local` (всего 20), организаторы `organizer02@sportmeet.local` … `organizer05@sportmeet.local` (всего 5), а также `venue-admin02@sportmeet.local` и `event-admin02@sportmeet.local`. Глобальный администратор один. Для всех начальный пароль одинаковый, но в базе хранятся **разные хеши scrypt с индивидуальными солями**; его можно заменить в разделе «Моя учётная запись».

Организаторы уже привязаны к четырём организациям, поэтому можно проверять создание встреч и обработку заявок с разных аккаунтов. У отдельных участников заранее есть заявки, очередь ожидания, уведомления и история прошедших встреч. Основной участник из таблицы свободен для проверки записи с чистого листа. Гость просматривает сайт без входа.

Встречи в комплектной базе созданы для локальной проверки функций. Их названия не содержат пометок, но фактическое проведение вне приложения не подтверждено. Для развёртывания с реальными пользователями удалите начальные записи и создайте собственные учётные записи с новыми паролями.
